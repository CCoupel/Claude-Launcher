Réglages — séparer le serveur des maquettes de l'interface web (#183)

Page « Ce poste » de la fenêtre Réglages. Aujourd'hui, un seul encadré « Navigateur » mélange les deux serveurs. Les propositions les séparent et ajoutent un commutateur pour l'interface web. Le champ « Adresse publique » vient de #171. Les encadrés bordés d'orange sont ceux qui changent ; le reste de la page est inchangé.

Règles communes à toutes les propositions

Commutateur : éteint par défaut. L'éteindre arrête le serveur de l'interface tout de suite et garde l'adresse saisie ; le rallumer le redémarre sur la même adresse, sans relancer le launcher.
Indépendance : éteindre l'interface web ne touche pas au serveur des maquettes, et inversement (« off » dans son champ d'écoute).
Depuis un navigateur (client web) : les deux sections sont en lecture seule, commutateur compris — règle de #163 inchangée.
Mode serveur (desktop --web, cas du pod Kubernetes) : l'interface web est le processus lui-même. Le commutateur est affiché allumé et verrouillé ; l'écoute et l'adresse publique sont celles du lancement (--addr, --url, valeurs du chart Helm). Un enabled: false du fichier est ignoré dans ce mode.
Fichier : backends.yaml → hubs.<machine>.desktop_web gagne enabled et url. Sans enabled, le comportement de la v6.2.0 est conservé (active si une écoute est renseignée).
