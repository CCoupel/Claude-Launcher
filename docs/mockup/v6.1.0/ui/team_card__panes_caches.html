Carte TEAM — teammates cachés / visibles · #136 · v6.1.0 · maquette retenue (A — Liste unique)

Composant : carte Team du volet d'état (interface native Windows et coque Linux) et son effet sur la fenêtre du projet. Un teammate inactif peut être caché : son pane quitte la fenêtre du projet, le teammate continue de tourner et reçoit ses messages ; il revient dès qu'il redevient actif. La maquette est manipulable : double-cliquer sur un teammate dans la carte, et utiliser la barre « Simulation » pour rendre un teammate actif ou inactif et faire passer le délai.

Règles

  • La carte liste chaque teammate (une ligne par instance lancée, plus les teammates du template non démarrés) — plus de regroupement « ×N ».
  • ● démarré, ○ non démarré. Ligne en surbrillance = son pane est visible dans la fenêtre du projet.
  • Un teammate actif est toujours visible : le double-clic est refusé (message en pied de volet). Caché, il réapparaît dès qu'il redevient actif.
  • Un teammate inactif se bascule par double-clic sur sa ligne : visible ↔ caché.
  • Masquage automatique : un inactif est caché après TEAM_HIDE_IDLE secondes (30 par défaut, 0 = jamais).
  • Un inactif rendu visible à la main reste visible jusqu'à un second double-clic. S'il redevient actif, il reprend la règle normale (caché 30 s après la fin de son activité).
  • Le leader (et un agent « cdp ») n'est jamais caché ; un pane ouvert à la main non plus ; l'inactif qui a le focus clavier n'est pas caché automatiquement.
  • Les panes visibles se partagent toute la fenêtre selon la règle actuelle (leader en haut ; ≤ 5 teammates sur une ligne, au-delà sur deux).
  • Un teammate caché continue de tourner et de recevoir ses messages ; fermer le projet ferme aussi ses teammates cachés.
  • Pas de raccourci clavier, pas d'indicateur « N cachés ». Projet en lecture seule (un autre launcher a la main) : le double-clic est refusé avec un message.
  • Même état sous Linux et Windows (option tmux @cl_panevis) : ce qui est caché d'un côté l'est de l'autre.
