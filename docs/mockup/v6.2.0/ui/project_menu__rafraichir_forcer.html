Menu du projet — « Rafraîchir » et « Forcer la fermeture » · #158 · v6.2.0 · maquette retenue (B — Bandeau d'étapes dans les cartes)

Composant : menu contextuel d'un projet (clic droit dans l'arbre, interface native Windows), avec l'indication affichée pendant l'opération et la confirmation de « Forcer la fermeture ». Les entrées existantes du menu sont inchangées. L'avancement s'affiche dans un bandeau d'étapes en tête des cartes du projet ; la fermeture forcée se confirme dans une boîte de dialogue. Cas montré : le projet ecagent est affiché avec une croix rouge alors que son pod k8s n'existe plus. L'équivalent de la coque Linux, validé le 2026-11-15, est en bas de page.

Parti pris : un bandeau d'étapes s'ouvre en tête des cartes du projet et coche chaque lecture (conteneur, session, git, GitHub, template) ; la confirmation de fermeture forcée est une boîte de dialogue qui liste ce qui sera nettoyé. Avantage : on voit ce qui est relu et ce qui a échoué ; la confirmation est explicite. Inconvénient : le bandeau décale les cartes pendant quelques secondes ; une fenêtre modale de plus.

Règles

  • Rafraîchir relit tout de suite, sans attendre les caches : existence et état du conteneur ou du pod, session et propriétaire, état git, milestone et issues GitHub, version du template, team, cartes. Raccourci : F5 sur le projet sélectionné (F5 garde en plus son effet global actuel).
  • La consommation du compte est redemandée, mais le délai minimal entre deux appels à l'API d'usage est respecté (protection contre les refus 429).
  • Après Rafraîchir, un projet dont le pod ou la session a disparu apparaît fermé (○) ; son onglet éventuel est retiré.
  • L'indicateur disparaît à la fin, y compris en cas d'erreur : un message dit alors ce qui n'a pas pu être relu.
  • Forcer la fermeture n'est proposée que si le projet est affiché ouvert ou en erreur alors que son conteneur, son pod ou sa session n'existe plus (ou ne répond plus). Sinon l'entrée est grisée ; « Fermer » reste l'action normale.
  • Elle nettoie l'état local : onglet, session tmux locale, panes cachés, marque de reprise, verrou de création resté en place ; elle demande l'arrêt du conteneur s'il existe encore. Rien n'est supprimé dans le projet ; l'attribution du backend (projects.json) est conservée.
  • Elle est refusée si un autre launcher pilote le projet (message : prendre la main d'abord).
  • « Fermer » devient disponible dès que quelque chose peut être fermé (aujourd'hui grisé si le projet n'a pas d'onglet dans cette fenêtre).
